# 05 · SDK: `@tap/core`

The protocol SDK. Pure TypeScript + viem. **Zero React Native / Expo imports** (INV-13). Runs in Bun (scripts, tests), in the app, and later on the web.

### Disabled sponsorship pilot (D36)
Additive exports `getPilotAccount(owner)`, `PilotAccount`, `PILOT_ACCOUNT_STACK`,
`pilotPaymentCalls`, `encodePilotPayment`, and `assertPilotPayment` select the pinned
Coinbase Smart Wallet 1.1 / EntryPoint 0.6 candidate on Base Sepolia only. Account
derivation is read-only, with one root EOA owner and factory nonce zero. The pilot
batch contains exactly USDC approval to canonical TapPay and the original `pay`
call, both zero value. Validation checks every call and canonical wrapper bytes.
These primitives neither authorize spending nor enable a provider. Live code,
provider, storage, budget and recovery approval remain gates; no teammate approval
is asserted by D36. Existing settlement APIs and merchant wire format are unchanged.

D37 adds `PilotOperation`, `PilotOperationWire`, `PilotLimits`, `PilotStatus`,
`PilotChallenge`, `PilotAction`, `PilotReceipt` and the operation serialization,
hashing, validation, owner signing/proof and receipt reconciliation helpers exported
from `src/index.ts`. Wire integers are canonical decimal strings, not JSON numbers.
Operation hashes bind Base Sepolia and EP 0.6. Proofs distinguish prepare/submit/status
and bind audience, owner, payer, request, calls, intent and preparation expiry.
Receipt success requires matching `Paid` within the matching EntryPoint operation's
log range; whole-bundle success or `isPaid` alone cannot attribute customer payment.

## Types 🔒 (`src/types.ts`)
```ts
import type { Address, Hash, Hex, LocalAccount, PublicClient } from "viem";

export type PaymentRequest = {
  merchant: Address;       // payout address AND signer
  token: Address;
  amount: bigint;          // token base units. NEVER number/float (INV-12)
  nonce: Hex;              // bytes32, 32 random bytes per charge
  expiry: bigint;          // unix seconds (uint64)
  merchantName: string;    // ENS-normalized, e.g. "yoyogi-market.tap.eth"
};

export type SignedRequest = {
  chainId: number;         // payment chain (84532)
  request: PaymentRequest;
  signature: Hex;          // merchant EIP-712 signature
};

export type VerifyFailure =
  | "malformed"            // fields don't parse / wrong shape
  | "unknown_chain"        // chainId not in allowlist
  | "unknown_token"        // token not in allowlist for chainId
  | "expired"              // now >= expiry
  | "bad_signature"        // signature isn't from `merchant` (EOA or ERC-1271)
  | "not_under_parent"     // name isn't a direct subname of ENS_PARENT
  | "ens_unresolved"       // name resolves to nothing / zero address
  | "ens_mismatch"         // name resolves to a different address
  | "network_error";       // couldn't reach ENS / RPC. NEVER treated as verified

export type VerifyResult =
  | { ok: true; ensName: string; displayName: string | null; tokenSymbol: string;
      displayAmount: string; expiresAt: Date }
  | { ok: false; reason: VerifyFailure };

export type PermitSig = { deadline: bigint; v: number; r: Hex; s: Hex };

export type MerchantProfile = { address: Address | null; displayName: string | null };

export type MerchantSetupCheck =
  | { ok: true; displayName: string | null }
  | { ok: false; reason: "not_under_parent" | "ens_unresolved" | "ens_mismatch" | "network_error" };

export type WalletBalances = {
  gas: { symbol: "ETH"; amount: bigint; display: string };
  tokens: { address: Address; symbol: string; amount: bigint; display: string }[];
};

export type TapConfig = {
  rpcUrls?: { payment?: string; ens?: string };  // defaults: public RPCs
  paymentClient?: PublicClient;                  // tests / advanced
  paymentWalletClient?: WalletClient;            // tests / advanced
  ensClient?: PublicClient;                      // tests / advanced
  ensWalletClient?: WalletClient;                // tests / advanced
  now?: () => Date;                              // tests only
};

export type { Address, Hash, Hex, LocalAccount };
```

## Public API 🔒 (`src/index.ts`)
| Function | Signature | Behaviour |
|---|---|---|
| `configureTap` | `(config?: TapConfig) => void` | Call once at startup. Idempotent; a later call replaces the config |
| `newChargeRequest` | `(o: { merchant: Address; merchantName: string; amount: bigint; token?: Address }) => PaymentRequest` | Normalizes the name, fills a random nonce and `expiry = now + REQUEST_TTL_SECONDS`, token defaults to USDC. Throws `TapInputError` if amount ≤ 0 or the token isn't allowlisted |
| `signRequest` | `(req: PaymentRequest, account: LocalAccount) => Promise<SignedRequest>` | EIP-712 sign with the TapPay domain for `PAYMENT_CHAIN_ID` |
| `hashRequest` | `(req: PaymentRequest, chainId?: number) => Hex` | EIP-712 digest. Must equal `TapPay.hashRequest` (INV-09) |
| `encodeRequestUrl` | `(s: SignedRequest) => string` | See wire format |
| `decodeRequestUrl` | `(url: string) => SignedRequest` | Throws `TapDecodeError` (`code: "malformed"`) |
| `verifyRequest` | `(s: SignedRequest) => Promise<VerifyResult>` | **Never throws.** Checks in the order below |
| `isUnderParent` | `(name: string) => boolean` | After `normalize`: matches `^[a-z0-9-]{3,32}\.<ENS_PARENT>$` exactly, no leading/trailing `-` |
| `resolveMerchant` | `(name: string) => Promise<Address \| null>` | Sepolia ENSv2; zero address → `null` |
| `getMerchantProfile` | `(name: string) => Promise<MerchantProfile>` | Address + text `name`, in parallel |
| `checkMerchantSetup` | `(name: string, address: Address) => Promise<MerchantSetupCheck>` | Merchant self-check (story M4) |
| `isMerchantLabelAvailable` | `(label: string) => Promise<boolean>` | Validates a direct label and checks the Sepolia registrar |
| `registerMerchant` | `(o: { label: string; displayName: string; owner: Address }, account: LocalAccount) => Promise<Hash>` | Validates ownership, simulates, registers, and waits for 1 Sepolia confirmation |
| `signPermit` | `(s: SignedRequest, account: LocalAccount) => Promise<PermitSig>` | EIP-2612: owner = account, spender = TapPay, value = amount, deadline = expiry, nonce from token, domain `name`/`version` read from the token (INV-11) |
| `payWithPermit` | `(s: SignedRequest, account: LocalAccount) => Promise<Hash>` | Offline pre-checks (allowlist, expiry) → `signPermit` → **simulate** → send. Throws `TapPayError` |
| `quoteSwap` | `(s: SignedRequest, input: "native" \| Address, options?) => Promise<SwapQuote>` | Quotes exact USDC output across configured v3 fee tiers, including WETH-bridged ERC-20 routes; returns an integer-rounded maximum bound to the request |
| `payWithSwap` | `(s: SignedRequest, account: LocalAccount, quote: SwapQuote) => Promise<Hash>` | Revalidates the quote/request binding, simulates, then pays through `TapSwapPay`; ERC-20 input uses Permit2 |
| `pay` | `(s: SignedRequest, account: LocalAccount) => Promise<Hash>` | Approve-based fallback: approves exactly `amount` if the allowance is short, then pays |
| `waitForPayment` | `(hash: Hash) => Promise<"success" \| "reverted">` | Waits for 1 confirmation |
| `isPaid` | `(merchant: Address, nonce: Hex) => Promise<boolean>` | Reads `TapPay.isPaid` |
| `watchPaid` | `(merchant: Address, nonce: Hex, onPaid: (tx: Hash \| null) => void) => () => void` | `watchContractEvent` filtered by `merchant` + `nonce` **plus** `isPaid` polling every 2s. Fires **exactly once** (`tx` is `null` if the poll wins), then stops both. Returns unsubscribe |
| `getWalletBalances` | `(address: Address) => Promise<WalletBalances>` | Base Sepolia ETH + every allowlisted token |
| `formatAmount` | `(amount: bigint, token?: Address) => string` | `"$5.00"` for USDC; decimals + symbol from the allowlist |
| `parseAmountInput` | `(input: string, token?: Address) => bigint` | `"5"`, `"5.0"`, `"5.00"` → `5_000_000n`. Rejects negatives, > token decimals, > `MAX_CHARGE`, junk → `TapInputError` |
| Account helpers | `generatePrivateKey`, `privateKeyToAccount` | Re-exported from viem so apps never import viem directly (INV-14) |
| Constants | `PAYMENT_CHAIN_ID`, `ENS_CHAIN_ID`, `ENS_PARENT`, `DEFAULT_TOKEN`, `REQUEST_TTL_SECONDS` | |
| Errors | `TapError`, `TapDecodeError`, `TapPayError`, `TapInputError`, `TapConfigError` | |

## `verifyRequest` order 🔒
Cheapest first, network last. Each step returns `{ ok: false, reason }` on failure.
1. Shape (addresses valid, amount > 0, nonce 32 bytes, name non-empty) → `malformed`
2. `chainId` in allowlist → `unknown_chain`
3. `token` in allowlist for that chain → `unknown_token`
4. `now < expiry` → `expired`
5. Signature: `recoverTypedDataAddress` == merchant (offline). If not equal, try `paymentClient.verifyTypedData` (ERC-1271 smart wallets) → `bad_signature`
6. `isUnderParent(merchantName)` → `not_under_parent`
7. `getMerchantProfile(name)`: RPC failure → `network_error`; null → `ens_unresolved`; `!isAddressEqual` → `ens_mismatch`
8. Success: `ensName`, `displayName` (from ENS), `tokenSymbol`, `displayAmount` (from allowlist) and `expiresAt`

## Wire format 🔒 (`src/request/url.ts`)
One NDEF URI record, target < 400 bytes:
```
https://tap-pay.xyz/p?v=1&c=<chainId>&m=<merchant>&n=<merchantName>&t=<token>&a=<amount>&x=<expiry>&k=<nonce>&s=<signature>
```
| Param | Field | Encoding / decode rule |
|---|---|---|
| `v` | version | must be `1`, else malformed |
| `c` | chainId | decimal integer |
| `m` | merchant | 0x + 40 hex → `getAddress` |
| `n` | merchantName | `encodeURIComponent` / decode, then `normalize` |
| `t` | token | 0x + 40 hex → `getAddress` |
| `a` | amount | decimal digits only → `BigInt`, > 0 |
| `x` | expiry | decimal digits only → `BigInt` |
| `k` | nonce | 0x + exactly 64 hex |
| `s` | signature | 0x + even-length hex, ≥ 65 bytes |

- The TapPay address is **never** in the URL; it comes from the allowlist by `c`.
- The decoder accepts **any host**, requires path `/p`, ignores unknown params, rejects missing or duplicate required params.
- The encoder always emits params in the order above (stable output, snapshot-testable).
- `tap-pay.xyz` is controlled by the team and is the canonical request/deep-link host (D26).

## Conventions
- Nonce: `toHex(crypto.getRandomValues(new Uint8Array(32)))` (the app loads `react-native-get-random-values` first).
- Expiry: `BigInt(Math.floor(now().getTime() / 1000) + REQUEST_TTL_SECONDS)`.
- EIP-712 domain: `{ name: "TapPay", version: "1", chainId, verifyingContract: paymentChains[chainId].tapPay }`.
- `PAYMENT_REQUEST_TYPES` field order and types must match the Solidity typehash exactly: `merchant:address, token:address, amount:uint256, nonce:bytes32, expiry:uint64, merchantName:string`.
- Compare addresses with `isAddressEqual`. Normalize names with `normalize` from `viem/ens`.
- `payWithPermit` / `pay` **simulate first** and map custom errors to `TapPayError` codes:

| Revert / condition | `TapPayError.code` |
|---|---|
| `Expired` | `expired` |
| `NonceUsed` | `already_paid` |
| `BadSignature` | `bad_signature` |
| `ZeroAmount` | `invalid_amount` |
| token balance < amount | `insufficient_funds` |
| ETH balance can't cover gas | `insufficient_gas` |
| RPC/network failure | `network` |
| anything else | `unknown` (keep the original error as `cause`) |

- No `any`. No `Number` math on amounts. Never log private keys or full signatures.
